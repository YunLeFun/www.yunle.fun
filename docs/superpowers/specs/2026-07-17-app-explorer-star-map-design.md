# 应用探索星图设计

## 背景

云乐坊首页宣称收录 10+ 自研或社区应用，但目前只展示模拟的应用市场预览；真实公开应用仅散落在详情页和用户主页。`useApps().getOfficialApps()` 已能读取官方账号发布的公开应用，适合作为第一版公共探索入口的数据源。

本功能要同时解决两个问题：

1. 用具有云乐坊辨识度的应用星图建立品牌记忆。
2. 让用户能够搜索、筛选、理解并进入真实应用，而不是只观看装饰动画。

## 目标

- 新增公开的 `/explore` 页面，展示当前全部官方公开应用。
- 首屏以星图建立品牌氛围，下方以应用矩阵承载高效发现。
- 星图和矩阵共享搜索与分类筛选状态。
- 桌面端提供完整星图体验；移动端保留品牌感，但优先保证矩阵可用性。
- 复用现有应用数据、Nuxt UI 和云乐坊设计变量，不引入 WebGL 或重量级图谱依赖。
- 支持键盘、触摸、减少动态效果和清晰的加载/失败/空状态。

## 非目标

- 本期不开放第三方开发者自助上架。
- 本期不接入推荐算法、评分、收藏量或实时热度排行。
- 本期不建设新的服务端搜索或数据库迁移流程。
- 本期不使用 Three.js、OGL、Cobe、Canvas 图标球或力导向图。
- 本期不替换独立应用站 `apps.yunle.fun`；公共探索页是主站内的生态橱窗。

## 方案比较

### 方案 A：星图在上、矩阵在下（采用）

用户先看到可交互星图，继续滚动后进入搜索和卡片矩阵。两层共享筛选结果。

优点是品牌展示不会被隐藏，矩阵仍提供稳定的信息获取路径；移动端也能自然降级。代价是页面较长，需要明确的滚动引导。

### 方案 B：星图和矩阵占用同一区域，通过开关切换

优点是页面紧凑；缺点是默认视图会隐藏另一种能力，用户可能不知道存在更实用的矩阵，状态切换也增加理解成本。

### 方案 C：矩阵为主体，星图只做背景装饰

优点是实现最简单、可用性稳定；缺点是星图无法承载应用关系，品牌记忆较弱，不符合本次创意展示目标。

## 页面与入口

- 新增 `app/pages/explore.vue`。
- 首页主 CTA“开始探索”从外部应用站改为 `/explore`。
- 独立应用站入口继续保留在站点菜单中，避免改变现有产品边界。
- `/explore` 服务端渲染标题、描述和静态页面框架；应用数据在客户端 CloudBase 就绪后加载。第一版不新增服务端管理凭据或数据代理。
- 应用节点和卡片进入现有 `/apps/:slug` 详情页；卡片可额外提供“打开应用”按钮，存在 `websiteUrl` 时新窗口打开该地址。

## 信息架构

页面从上到下分为四段：

1. **探索标题区**：页面标题、生态说明、应用数量和向下探索提示。
2. **应用星图**：分类星座、应用节点、连线、悬停或聚焦预览。
3. **发现工具栏**：搜索框、分类筛选、结果数量和清除筛选。
4. **应用矩阵**：响应式卡片网格，以及加载失败、空结果和无应用状态。

## 数据与元数据

### 数据源

页面调用现有 `getOfficialApps()`，只展示满足以下条件的记录：

- `ownerLogin` 属于官方账号。
- `isPublic` 为 `true`。

它与当前开发者平台未开放的业务规则一致。未来开放社区上架后，只需替换页面的数据提供函数，不改变星图和矩阵组件接口。

### 展示元数据

应用名称、描述、图标、Logo、Emoji、主题色和链接继续来自 `AppRecord`。新增 `app/config/app-explorer.ts`，只保存可选的展示覆盖信息：

- `category`：所属星座和筛选分类。
- `tags`：参与搜索的短标签。
- `featured`：是否靠近星图核心展示。
- `accent`：缺少 `themeColor` 时的品牌色覆盖。

配置以 `slug` 为键；没有配置的公开应用仍自动出现，分类回退为“其他”，颜色由 `slug` 稳定派生。这样不需要迁移数据库，也不会把应用 URL 或名称复制到配置中。

### 派生模型

新增纯函数把 `AppRecord[]` 与展示配置合并为 `ExplorerApp[]`。页面组件只消费派生模型，不直接了解 CloudBase 或配置细节。

## 星图设计

### 布局

- 星图核心显示云乐坊标识与当前应用数量。
- 每个分类拥有一个稳定的锚点；应用按 `slug` 排序后围绕锚点分布。
- 位置由稳定字符串哈希、分类锚点和黄金角共同计算，同一数据集刷新后不会乱跳。
- 布局函数执行固定次数的确定性防碰撞调整，保证节点具有最小间距。
- `featured` 应用更靠近核心并拥有略大的节点，其余节点尺寸一致，不伪造热度含义。

### 连线

- 一个 SVG 覆盖层绘制所有连线，不为每条边创建独立观察器或动画组件。
- 核心与分类锚点相连，同分类应用按稳定顺序形成短链；不表达虚构的数据依赖关系。
- 连线使用低透明度静态轨道，少量渐变光束沿轨道移动。
- 搜索或筛选后只绘制可见节点相关的连线。

### 节点与交互

- 应用节点使用真实的 `NuxtLink` DOM 元素而不是 Canvas 绘制，因此可聚焦、可读屏并保留链接语义。
- 悬停、键盘聚焦或触摸节点时显示应用名称、描述和分类。
- 点击节点进入 `/apps/:slug`。
- 当前聚焦节点提高相关连线和同分类节点的亮度，其余节点轻微降权。
- 背景星点不参与交互，也不进入辅助技术的阅读顺序。

### 动效与性能

- 背景借鉴 Inspira UI `Stars Background` 的分层视差语言，但使用少量确定性星点和 CSS 变换，不生成上千个随机 `box-shadow`。
- 连线借鉴 `Animated Beam` 的 SVG 渐变光束思路，但合并到单个 SVG。
- 不引入 `motion-v`、`@inspira-ui/plugins` 或 WebGL 依赖。
- `prefers-reduced-motion: reduce` 下停止视差、漂浮和光束位移动画，保留静态层次。
- 星图离开视口后暂停非必要动画。

## 应用矩阵设计

- 桌面端使用三列或四列响应式网格，平板两列，手机单列。
- 每张卡片包含图标、名称、描述、分类、标签、作者和主操作。
- 卡片借鉴 Inspira UI `Card Spotlight` 的径向聚光效果，移植为本地组件并改用云乐坊颜色变量。
- 鼠标聚光只作为增强；键盘聚焦使用清晰边框和静态光晕，不依赖指针位置。
- 图片加载失败时回退到 Emoji，再回退到通用应用图标。
- 搜索匹配名称、描述、分类、标签和 `slug`，使用不区分大小写的包含匹配。
- 分类筛选与搜索组合使用；“清除筛选”恢复全部应用。

## 响应式策略

- `lg` 及以上显示完整星图、连线和预览浮层。
- 中等屏幕降低节点密度和连线动画数量，但保留所有应用节点。
- 手机显示紧凑星图：较小的核心、无动画连线和可横向探索的节点区域；页面首屏同时露出“浏览应用矩阵”入口。
- 矩阵始终展示全部筛选结果，是所有设备上的可靠兜底路径。

## 组件边界

- `app/pages/explore.vue`：数据加载、页面状态、筛选状态和区块编排。
- `app/components/apps/AppExplorerHero.vue`：标题、统计和滚动引导。
- `app/components/apps/AppStarMap.vue`：星图容器、节点和预览交互。
- `app/components/apps/AppConstellationLines.vue`：单 SVG 连线和光束。
- `app/components/apps/AppDiscoveryToolbar.vue`：搜索、分类筛选和结果数量。
- `app/components/apps/AppDiscoveryGrid.vue`：矩阵、空状态和卡片列表。
- `app/components/apps/AppDiscoveryCard.vue`：单应用卡片和聚光增强。
- `app/composables/useAppExplorer.ts`：数据合并、过滤和派生状态。
- `app/utils/app-star-layout.ts`：无 Vue 依赖的确定性布局纯函数。
- `app/config/app-explorer.ts`：按 `slug` 管理的可选展示元数据。

组件通过显式 props 和事件通信。只有页面负责获取数据；展示组件不访问 CloudBase。

## 加载与错误处理

- 初始加载显示与最终布局尺寸接近的骨架，避免页面跳动。
- CloudBase 请求失败时显示错误说明和“重新加载”按钮，首页和其他页面不受影响。
- 数据源为空时显示“应用正在汇聚中”的品牌化空状态。
- 搜索无结果时保留工具栏并提供清除筛选操作。
- 单个应用图标失败不会影响整页，按统一回退链展示。
- 配置里存在数据库中已删除的 `slug` 时静默忽略；数据库中新应用没有配置时自动归入“其他”。

## 可访问性

- 星图节点和卡片均使用链接语义，并包含应用名称的可访问标签。
- 所有仅装饰的 SVG、星点和光束设置 `aria-hidden="true"`。
- 焦点顺序与应用的稳定排序一致，不跟随视觉坐标乱序。
- 预览信息不能只在 hover 出现，`focus-visible` 和触摸点击也能触发。
- 文本、边框与主题色满足现有亮色和暗色模式的对比度约束。
- 动效不会阻塞操作，减少动态效果偏好下页面完全可用。

## Inspira UI 使用边界

Inspira UI 采用 MIT 许可证并鼓励复制、定制组件。本功能采取以下策略：

- 直接参考 `Card Spotlight` 的轻量指针聚光实现，改写为项目组件。
- 参考 `Animated Beam` 的 SVG 渐变光束算法，合并成适合多节点的单 SVG 实现。
- 参考 `Stars Background` 的分层视差视觉，不复制其随机星点和 `motion-v` 实现。
- 不使用 `Icon Cloud` 作为主导航，因为 Canvas 不适合承载每个应用的链接和键盘语义。
- 不使用 `Globe`、`Infinite Grid`、`Cosmic Portal` 等 WebGL 组件。
- 对实质移植的源码保留来源、上游链接和 MIT 许可说明。

## 测试策略

### 单元测试

- 相同 `slug` 和分类输入始终产生相同坐标。
- 不同输入规模下坐标保持在边界内，节点达到约定最小间距。
- 元数据合并正确处理覆盖、默认分类和默认颜色。
- 搜索匹配名称、描述、标签、分类和 `slug`。
- 搜索与分类筛选正确组合，清除后恢复全部数据。

### 组件测试

- 加载、失败、空数据和无搜索结果状态正确渲染。
- 星图节点和矩阵卡片链接到正确详情页。
- 键盘聚焦能显示节点预览并更新高亮状态。
- 图片失败按图标回退链处理。
- 减少动态效果模式下不渲染持续位移动画。

### 页面验证

- 执行 ESLint、Nuxt 类型检查和相关 Vitest 测试。
- 在桌面和手机视口检查布局、触摸目标、滚动和暗色模式。
- 检查页面没有新增 Three.js、OGL、Cobe 或 `motion-v` 依赖。

## 验收标准

- 未登录用户可从首页进入 `/explore` 并看到全部官方公开应用。
- 首屏星图具有稳定布局，刷新后节点不会随机重排。
- 用户可通过搜索和分类筛选同时缩小星图与矩阵结果。
- 任一应用都能通过键盘在星图或矩阵中进入详情页。
- 手机端无需操作复杂星图即可浏览完整应用矩阵。
- 数据失败、空数据、无结果和图标失败均有可理解的回退。
- 功能不新增重量级图形依赖，并遵守上游 MIT 许可要求。
