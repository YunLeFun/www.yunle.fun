# 云端应用图谱设计

## 背景

云乐坊首页宣称收录 10+ 自研或社区应用，但目前只展示模拟的应用市场预览；真实公开应用仅散落在详情页和用户主页。`useApps().getOfficialApps()` 已能读取官方账号发布的公开应用，适合作为第一版公共探索入口的数据源。

本功能要同时解决两个问题：

1. 用延续“云之彼端 · 梦幻晴空”设计体系的统一账号云图建立品牌记忆，并准确表达第一方 Web SSO 关系。
2. 让用户能够搜索、筛选、理解并进入真实应用，而不是只观看装饰动画。

## 目标

- 新增公开的 `/explore` 页面，展示当前全部官方公开应用。
- 首屏以真实 SSO Client Registry 驱动的账号云图建立品牌氛围，下方以应用矩阵承载高效发现。
- 账号云图只展示启用中的 Web SSO 应用；应用矩阵展示全部官方公开应用。
- 桌面端提供完整云图体验；移动端保留品牌感，但优先保证矩阵可用性。
- 复用现有应用数据、Nuxt UI 和云乐坊设计变量，不引入 WebGL 或重量级图谱依赖。
- 支持键盘、触摸、减少动态效果和清晰的加载/失败/空状态。

## 灵感注记

“账号云港”可作为统一账号云图的设计意象：应用云像停靠在云端港湾中的节点，云乐坊账号则是连接这些应用的通行凭证。“云港”也自然联想到创作者的家乡连云港，为云乐坊的云端叙事增加了一层个人的地理记忆。现阶段它作为内部设计灵感保留，未来可用于品牌故事或页面彩蛋。

## 非目标

- 本期不开放第三方开发者自助上架。
- 本期不接入推荐算法、评分、收藏量或实时热度排行。
- 本期不建设新的服务端搜索或数据库迁移流程。
- 本期不使用 Three.js、OGL、Cobe、Canvas 图标球或力导向图。
- 本期不替换独立应用站 `apps.yunle.fun`；公共探索页是主站内的生态橱窗。

## 方案比较

### 方案 A：云图在上、矩阵在下（采用）

用户先看到可交互的统一账号生态图，继续滚动后进入搜索和卡片矩阵。首屏只表达真实的账号连接，矩阵负责完整的应用发现。

优点是品牌展示不会被隐藏，矩阵仍提供稳定的信息获取路径；移动端也能自然降级。代价是页面较长，需要明确的滚动引导。

### 方案 B：云图和矩阵占用同一区域，通过开关切换

优点是页面紧凑；缺点是默认视图会隐藏另一种能力，用户可能不知道存在更实用的矩阵，状态切换也增加理解成本。

### 方案 C：矩阵为主体，云层只做背景装饰

优点是实现最简单、可用性稳定；缺点是云层无法承载应用关系，品牌记忆较弱，不符合本次创意展示目标。

## 页面与入口

- 新增 `app/pages/explore.vue`。
- 首页主 CTA“开始探索”从外部应用站改为 `/explore`。
- 首页通过 `HomeAppShowcase` 复用同一账号云图并提供“浏览全部应用”入口；完整搜索和应用矩阵仍由 `/explore` 承载。
- 独立应用站入口继续保留在站点菜单中，避免改变现有产品边界。
- `/explore` 服务端渲染标题、描述和静态页面框架；应用数据在客户端 CloudBase 就绪后加载。第一版不新增服务端管理凭据或数据代理。
- 应用云岛和卡片进入现有 `/apps/:slug` 详情页；卡片可额外提供“打开应用”按钮，存在 `websiteUrl` 时新窗口打开该地址。

## 信息架构

页面从上到下分为四段：

1. **探索标题区**：页面标题、生态说明、应用数量和向下探索提示。
2. **统一账号应用云图**：账号主云、启用中的 Web SSO 应用云、语义化云路与登录状态。
3. **发现工具栏**：搜索框、分类筛选、结果数量和清除筛选。
4. **应用矩阵**：响应式卡片网格，以及加载失败、空结果和无应用状态。

## 数据与元数据

### 数据源

页面包含两个独立数据源：

- 统一账号云图从 `packages/authorization-core/src/registry.ts` 的 production registry 派生，只展示 `status: active` 且包含 `web-sso` adapter 的客户端。
- 应用矩阵调用现有 `getOfficialApps()`，只展示满足以下条件的记录：

- `ownerLogin` 属于官方账号。
- `isPublic` 为 `true`。

应用矩阵与当前开发者平台未开放的业务规则一致。SSO 状态不得在应用展示配置中另设布尔字段，避免与授权真源漂移。

首页与 `/explore` 的账号云图直接导入构建时 Registry 快照，不发起数据库请求；因此首页刷新时应立即拥有完整应用节点。只有 `/explore` 的官方应用矩阵需要在客户端查询 CloudBase。Registry 的持久化和发布约定见 [`docs/sso-integration.md`](../../sso-integration.md#registry-存储与发布模型)。

### 展示元数据

公开应用名称、描述、图标、Logo、Emoji、主题色和链接继续来自 `AppRecord`。`app/config/app-explorer.ts` 只保存可选的矩阵展示覆盖信息：

- `category`：所属云群和筛选分类。
- `tags`：参与搜索的短标签。
- `featured`：是否靠近云图核心展示。
- `accent`：缺少 `themeColor` 时的品牌色覆盖。

配置以 `slug` 为键；没有配置的公开应用仍自动出现，分类回退为“其他”，颜色由 `slug` 稳定派生。这样不需要迁移数据库，也不会把应用 URL 或名称复制到配置中。

SSO 应用的 `clientId`、`appId`、状态、名称、Origin 和客户端自有 `iconUrl` 来自授权 Registry；`app/config/sso-explorer.ts` 只补充主题色、简短描述、失败回退字标和确定性视觉坐标。

### 派生模型

纯函数把 `AppRecord[]` 与展示配置合并为 `ExplorerApp[]`。SSO 展示配置把 Registry 客户端投影为 `SsoExplorerApp[]`。页面组件不自行判断某应用是否支持 SSO。

## 云图设计

### 账号主云

- 云图复用 `SkyScene` 的晴空、云层和黄昏语言，中央略偏下显示一朵具有宽平底部和多个自然云峰的账号主云。
- 主云使用可缩放 SVG 轮廓与代码原生文本，不再用椭圆加圆形伪元素拼接。
- 未登录时主云显示“云乐坊账号 / 登录后连接应用”，点击进入带 `/explore` 回跳的登录页。
- 已登录时显示用户头像、昵称和“已连接”，点击进入个人中心。
- 访客或真实账号未设置头像时使用不对应真人身份的通用云朵机器人头像；已设置头像的用户始终优先展示自己的头像。
- 服务端与客户端首次渲染统一使用 pending 状态，挂载后再同步真实登录态，避免 hydration mismatch。

### SSO 应用云与云路

- 只渲染 Registry 中启用的 Web SSO 客户端；停用客户端和 device adapter 不进入云图。
- 桌面端账号主云位于中央略偏下，应用云按 Registry 中的启用数量在左右两侧均衡排布；当前八个应用云左右各四。
- 应用云直接显示真实 Logo、名称和“统一账号”状态；Logo 加载失败时回退到品牌色字母图标，不使用 Emoji。
- 应用云主链接在新标签页直接打开 Registry Origin；有站内详情的应用额外提供次级详情入口。
- 一个 SVG 覆盖层只绘制真实 SSO 连接。默认云路是低对比度宽光带；悬停或键盘聚焦某个应用时，仅对应云路提亮并播放一次流光。
- 不再渲染分类标签、全应用节点、虚构关系或独立悬浮预览卡。

### 动效与性能

- 背景直接复用现有 `SkyScene`，浅色模式呈现晴空白日，深色模式呈现蓝紫黄昏，不另建宇宙或夜空视觉体系。
- 账号主云和应用云不持续漂浮；只有远景云层缓慢移动。
- 云路借鉴 Inspira UI `Animated Beam` 的 SVG 渐变光束思路，但改写为交互触发的一次性流光。
- 不引入 `motion-v`、`@inspira-ui/plugins` 或 WebGL 依赖。
- `prefers-reduced-motion: reduce` 下停止视差、漂浮和光束位移动画，保留静态层次。
- 云图离开视口后暂停非必要动画。

## 应用矩阵设计

- 桌面端使用三列或四列响应式网格，平板两列，手机单列。
- 每张卡片包含图标、名称、描述、分类、标签、作者和主操作。
- 卡片借鉴 Inspira UI `Card Spotlight` 的径向聚光效果，移植为本地组件并改用云乐坊颜色变量。
- 鼠标聚光只作为增强；键盘聚焦使用清晰边框和静态光晕，不依赖指针位置。
- 图片加载失败时回退到 Emoji，再回退到通用应用图标。
- 搜索匹配名称、描述、分类、标签和 `slug`，使用不区分大小写的包含匹配。
- 分类筛选与搜索组合使用；“清除筛选”恢复全部应用。

## 响应式策略

- `lg` 及以上显示完整云图与云路。
- 中等屏幕降低航迹动画数量，但保留所有应用云岛。
- 手机不缩放桌面图：顶部显示账号主云，下方以一条短云路连接可横向滚动、带 scroll snap 的 SSO 应用云列表；页面首屏露出“浏览全部应用”入口。
- 矩阵始终展示全部筛选结果，是所有设备上的可靠兜底路径。

## 组件边界

- `app/pages/explore.vue`：数据加载、页面状态、筛选状态和区块编排。
- `app/components/apps/AppExplorerHero.vue`：标题、统计和滚动引导。
- `app/components/apps/AppSsoCloudMap.vue`：账号云图容器和桌面/移动编排。
- `app/components/apps/SsoAccountCloud.vue`：账号主云、登录状态和账户入口。
- `app/components/apps/SsoAppCloud.vue`：单个 Registry 客户端的真实 Logo、状态和应用入口。
- `app/components/apps/SsoCloudRoutes.vue`：真实 SSO 云路和交互流光。
- `app/components/apps/AppDiscoveryToolbar.vue`：搜索、分类筛选和结果数量。
- `app/components/apps/AppDiscoveryGrid.vue`：矩阵、空状态和卡片列表。
- `app/components/apps/AppDiscoveryCard.vue`：单应用卡片和聚光增强。
- `app/composables/useAppExplorer.ts`：数据合并、过滤和派生状态。
- `app/config/app-explorer.ts`：按 `slug` 管理的可选展示元数据。
- `app/config/sso-explorer.ts`：从 Registry 派生 SSO 应用，只补充视觉展示元数据。

组件通过显式 props 和事件通信。只有页面负责获取数据；展示组件不访问 CloudBase。

## 加载与错误处理

- 初始加载显示与最终布局尺寸接近的骨架，避免页面跳动。
- CloudBase 请求失败时显示错误说明和“重新加载”按钮，首页和其他页面不受影响。
- 数据源为空时显示“应用正在汇聚中”的品牌化空状态。
- 搜索无结果时保留工具栏并提供清除筛选操作。
- 单个应用图标失败不会影响整页，按统一回退链展示。
- 配置里存在数据库中已删除的 `slug` 时静默忽略；数据库中新应用没有配置时自动归入“其他”。

## 可访问性

- SSO 应用云和矩阵卡片均使用链接语义，并包含应用名称、统一账号状态和新标签页提示。
- 所有仅装饰的 SVG、云层、飞鸟和光线设置 `aria-hidden="true"`。
- 焦点顺序与应用的稳定排序一致，不跟随视觉坐标乱序。
- 预览信息不能只在 hover 出现，`focus-visible` 和触摸点击也能触发。
- 文本、边框与主题色满足现有亮色和暗色模式的对比度约束。
- 动效不会阻塞操作，减少动态效果偏好下页面完全可用。

## Inspira UI 使用边界

Inspira UI 采用 MIT 许可证并鼓励复制、定制组件。本功能采取以下策略：

- 直接参考 `Card Spotlight` 的轻量指针聚光实现，改写为项目组件。
- 参考 `Animated Beam` 的 SVG 渐变光束算法，改写并合并成适合多云岛的单 SVG 航迹实现。
- 不使用 `Stars Background`；背景复用云乐坊现有 `SkyScene`，保持“梦幻晴空”品牌一致性。
- 不使用 `Icon Cloud` 作为主导航，因为 Canvas 不适合承载每个应用的链接和键盘语义。
- 不使用 `Orbit`，避免重新引入星体轨道隐喻。
- 不使用 `Globe`、`Infinite Grid`、`Cosmic Portal` 等 WebGL 组件。
- 对实质移植的源码保留来源、上游链接和 MIT 许可说明。

## 测试策略

### 单元测试

- 相同 `slug` 和分类输入始终产生相同坐标。
- 不同输入规模下坐标保持在边界内，云岛达到约定最小间距。
- 元数据合并正确处理覆盖、默认分类和默认颜色。
- 搜索匹配名称、描述、标签、分类和 `slug`。
- 搜索与分类筛选正确组合，清除后恢复全部数据。

### 组件测试

- 加载、失败、空数据和无搜索结果状态正确渲染。
- SSO 应用云链接到 Registry Origin，账号主云链接到登录页或个人中心。
- 键盘聚焦只提亮对应云路，减少动态效果模式下不渲染流光。
- SSO Registry 投影排除停用客户端与非 Web adapter。
- 图片失败按图标回退链处理。
- 减少动态效果模式下不渲染持续位移动画。

### 页面验证

- 执行 ESLint、Nuxt 类型检查和相关 Vitest 测试。
- 在桌面和手机视口检查布局、触摸目标、滚动和暗色模式。
- 检查页面没有新增 Three.js、OGL、Cobe 或 `motion-v` 依赖。

## 验收标准

- 未登录用户可从首页进入 `/explore` 并看到全部官方公开应用。
- 首屏账号云图只展示 Registry 中真实启用的 Web SSO 应用，连线不暗示不存在的账号关系。
- 账号主云的形状可立即识别为云，并在登录后显示真实账号状态。
- 用户可通过搜索和分类筛选应用矩阵；筛选不改变 SSO 账号云图。
- SSO 应用可通过键盘直接打开应用，存在站内详情时可进入详情页。
- 手机端无需操作复杂云图即可浏览完整应用矩阵。
- 数据失败、空数据、无结果和图标失败均有可理解的回退。
- 功能不新增重量级图形依赖，并遵守上游 MIT 许可要求。
