# 云食册原生微信登录

云食册用移动应用 AppID `wxce6c7405dd756b9d` 调起微信。现有 `https://api.yunle.fun/sso-ticket` 的两个原生动作负责向微信换码、验证绑定和签发原云乐坊 UID 的 custom ticket。网站仍按原流程使用 `wx_open`；不修改其 AppID、AppSecret、回调、SDK 或绑定。

首次绑定在云食册内完成。App 提供已有云乐坊会话和微信授权码；函数通过同环境 CloudBase `/auth/v1/user/me` 取得原 UID，通过移动应用 AppSecret 向微信换取 UnionID，并在写入前复查会话仍属于同一 UID、账号符合现有登录规则。原生绑定不依赖网站的 `wx_open`。不能用昵称、头像或跨应用 OpenID 判定身份。

索引在同一个事务内写入，一个对应微信身份，一个对应 CloudBase UID。并发绑定不能覆盖已有归属；同一对重复绑定幂等。保存的只有 UID、带独立密钥的 UnionID 摘要和创建时间，不保存微信 token 或原始标识。以后用微信登录时重新核对该 UID 的账号状态和登录资格；冻结、注销或身份无法确认时不签票。网站绑定的变更不撤销云食册绑定。未绑定的微信不会自动开户、合并或迁移数据。

## 配置与部署顺序

1. 核对开放平台「微信登录」已开通、AppID/Bundle ID/Universal Links 一致，且移动应用换码确实返回 UnionID。
2. 在对应 CloudBase 环境建立服务端专用文档集合 `sso_cook_wechat_bindings`（客户端读写均关闭），为 `uid` 建非唯一索引供注销清理。新建 PostgreSQL 环境先启用 Document（`pgdoc`）插件，并验证文档事务和集合权限。先部署 [account-api](https://github.com/YunLeFun/api) 中删除绑定记录的清理，再部署 `sso-ticket` 新代码。`sso_security_limits` 保存单次授权码摘要并由 `sso-security-sweeper` 清理。已有环境使用只更新代码的部署流程，保留函数路由、ACL 和其他变量。
3. 在目标环境的 **云函数 → sso-ticket → 配置 → 环境变量** 单独合并下列值。联调须使用已核实的独立 CloudBase 环境、对应的 Registry 和测试构建。`sso-ticket` 从函数运行上下文读取实际环境 ID 来验证会话，不接受客户端指定环境。不要向生产环境的 CloudBase「身份认证 → 登录方式」添加或覆盖微信身份源。

| 变量                         | 值                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `COOK_WECHAT_APP_SECRET`     | 微信开放平台「云食册」**移动应用**的 AppSecret，只填这里                               |
| `COOK_WECHAT_BINDING_KEY`    | 每环境独立的 32 字节随机密钥，64 位十六进制，持久保存；不要在轮换 AppSecret 时一同更换 |
| `COOK_WECHAT_LOGIN_ENABLED`  | 缺省关闭；仅为已准备好的联调环境显式设为 `true`                                        |
| `COOK_WECHAT_SIGNUP_ENABLED` | 缺省关闭；依赖微信登录开关，单独控制显式注册                                           |

4. 开关关闭时核对原 SSO 换码和 JWKS 不变。联调确认本人 `/auth/v1/user/me` 与管理员 `getEndUserInfo(uid)` 能验证同一原 UID，以及绑定索引的双向事务可用。
5. 用装有微信的 iPhone 和没有网站微信绑定的账号验证 App 内绑定，退出后重新用微信登录，并在本机比较实际会话 UID。另测未绑定微信、并发冲突、账号注销、取消和重复回调。正式开放前补齐原生绑定的自助撤销路径、隐私和 App Review 验收。

这些变量不属于普通部署清单，避免现有发布要求填写额外密钥。已配置的环境只走保留环境变量的代码更新；如必须全量更新配置，先保全这些值并核对更新后的开关。

回滚先将 `COOK_WECHAT_LOGIN_ENABLED` 设为 `false`，再按需恢复函数代码；不改网站身份源、不删除索引。若账号需要改绑另一个微信，旧索引会阻止自动覆盖；先由支持渠道核实账号归属，再处理索引。

## 在云食册注册新账号

注册动作与 `exchangeCookWeChatCode` 分开。先调用 CloudBase 短信验证（必要时完成图片验证码），验码后才用服务端 `queryUserInfo` 查手机号，已有账号只返回登录提示。新用户确认并授权微信后，再查一次手机号；后端占用微信身份、消费一次性手机号证明，然后调用 CloudBase 的显式 `signup`。复核新 UID、手机号和账号状态后才写入微信绑定并签票。并发由 CloudBase 手机号唯一性及微信身份的事务预留共同保护。

短信挑战和手机号证明经加密后短暂保留在 App 内存，绑定本次设备 ID；手机号、短信码和微信授权码不写入文档集合或日志。临时预留和重放摘要由现有 `sso_security_limits` 清理任务回收。若已开户但绑定或登录中断，保留该手机号账号，提示用手机号登录后检查绑定。

启用前用隔离环境真实验证已注册手机号、全新手机号、图片验证码、CloudBase 重复手机号拒绝及登录后的同 UID。确认客户端和服务端默认关闭，避免改变网站的手机号注册及微信配置。
