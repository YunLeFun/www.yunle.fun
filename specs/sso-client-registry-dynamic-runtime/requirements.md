# SSO Client Registry 动态裁决需求决策记录

状态：Deferred（2026-08-03）

当前实施入口：`../sso-client-registry-static-release/`

平台基础：`../sso-client-registry-platform/`

## 决策

生产环境继续把 generated 静态 Registry JSON 作为唯一授权裁决源。管理平台可以保存草稿、校验 Schema、生成差异、维护审计并生成候选产物，但数据库内容、活动指针或公开接口均不直接参与生产授权。

production 变更仍须把一次性审批码发送到管理员不可变 uid 当前绑定的已验证邮箱；邮箱地址不得硬编码。审批成功后自动生成 JSON，由 CI 执行验证和部署。签名快照、版本、回滚与 shadow 校验继续保留。

## 当前必须满足的结果

- 所有生产授权函数读取同一份构建期 generated JSON。
- generated JSON 必须经过严格 Schema、安全约束、canonical hash 和签名验证。
- 发布必须可追溯到草稿、差异、审批、生成产物、CI 结果和部署版本。
- 回滚必须选择历史签名快照、生成新版本并重新经过 CI，不直接改线上数据库指针。
- shadow 读取或比较失败不得改变静态授权结果，也不得增加请求热路径上的数据库依赖。
- 新客户端、停用客户端和安全字段变更均通过独立 Registry 变更记录审阅。

详细验收标准由静态发布规格维护，本记录不再复制。

## 暂缓能力

- 动态快照作为正式裁决源
- 运行时缓存刷新、租约续签和 last-known-good 陈旧窗口
- generation / lease 防重放水位
- 公开动态应用投影接口
- 数据库故障时的动态 fail-closed / break-glass 模式切换
- 无需部署即可传播普通 Registry 变更

这些能力没有 Tasks，也不得从本记录直接进入实现。

## 暂缓原因

当前 Registry 规模小，generated 产物约为 KiB 级；构建期加载与 Map 索引已使常规查询保持 O(1)。动态裁决会额外引入每个暖实例的数据库探测、缓存一致性、租约续签、重放防护、公开接口和告警运维成本，现阶段没有可验证的性能或成本收益。

## 复评触发条件

满足任一条件时可以重新建立独立 Requirements、Design 与 Tasks，并重新确认安全取舍：

- Registry 变更频率高到 CI 部署成为明确交付瓶颈；
- 客户端数量或 generated 产物大小接近现有构建/冷启动预算；
- 出现必须在部署窗口外紧急停用客户端的合规要求；
- 多个 Provider 需要共享同一活动策略，静态发布无法维持一致性；
- 已具备动态数据面的 SLO、告警、演练和长期运维负责人。

复评前，任何“免部署更新”都只能停留在管理草稿层，不能改变生产裁决。
